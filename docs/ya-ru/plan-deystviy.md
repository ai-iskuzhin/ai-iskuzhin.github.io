# План действий

Что менять, чтобы Яндекс смог сформировать быстрые ссылки. Проблемы
пронумерованы как в [analiz-sayta.md](analiz-sayta.md).

Порядок важен: правки первого этапа дешёвые и безопасные, второй этап —
разовое решение о структуре сайта, менять которое потом дорого (каждое
переименование раздела обнуляет накопленный сигнал и запускает переформирование
быстрых ссылок с нуля).

> Ничего из перечисленного ещё не применено — это план, а не changelog.

---

## Этап 1. Техническая гигиена

Мелкие правки, ничего не ломают, делают внутренние ссылки чистыми.

### 1.1. Убрать 301 с внутренних ссылок (проблема 3)

Сейчас canonical — `/open-source/`, а все ссылки ведут на `/open-source` и
получают 301. Нужно, чтобы ссылка, canonical и sitemap называли **один и тот же
адрес**.

Правки в [src/routes.ts](../../src/routes.ts): построители путей должны
возвращать адрес со слешем на конце.

```ts
export function librariesPath(lang: Lang): string {
  return `${prefix(lang)}/open-source/`
}
```

— и так же `libraryPath`, `verificahubPath`, `blogPath`, `postPath`,
`homePath('en')` → `/en/`.

Что при этом уже работает и ломаться не должно:

- `matchRoute()` снимает хвостовой слеш в `normalize()` — маршрутизация не
  меняется;
- `absolute()` в [src/seo.ts:42](../../src/seo.ts#L42) не добавляет второй слеш,
  если он уже есть;
- `outputFile()` в [scripts/prerender.mjs:36](../../scripts/prerender.mjs#L36)
  раскладывает `/open-source/` в `dist/open-source/index.html` — как и сейчас.

После сборки проверить, что в `dist/index.html` ссылки стали `href="/open-source/"`,
а `sitemap.xml` не изменился.

### 1.2. Починить анкор «Обо мне» в подвале (проблема 4)

[src/components/Footer.tsx:19](../../src/components/Footer.tsx#L19) отдаёт ссылку
на `/` с текстом «Обо мне». На главной это ссылка на саму себя, и она приписывает
анкор «Обо мне» главной странице.

Либо вести на `#about` (`${homePath(lang)}#about`), либо переименовать анкор в
имя сайта. После этапа 2, если появится страница `/about/`, — вести на неё.

### 1.3. Поправить домен в README

[README.md](../../README.md) указывает `https://ai-iskuzhin.github.io`, а
реальный хост — `ai-iskuzhin.is-a.dev` (`public/CNAME`, `SITE.baseUrl`).

### 1.4. Проверить хлебные крошки валидатором

Прогнать `/open-source/yookassanet/` через
[валидатор микроразметки](https://webmaster.yandex.ru/tools/microtest/).
Если `BreadcrumbList` из JSON-LD не распознаётся — продублировать крошки
микроразметкой в вёрстке. Подробнее в [snippet.md](snippet.md).

## Этап 2. Структура меню

Здесь и решается, будут ли быстрые ссылки вообще. Условие Яндекса: «разделы и
подразделы выделены в меню», а быстрая ссылка — это ссылка **на другой URL**.
Сейчас реальных страниц в меню две.

Нужно выбрать один из двух вариантов.

### Вариант A. Минимальный — добавить VerificaHub в меню

Одна правка в [src/components/Header.tsx:31-38](../../src/components/Header.tsx#L31-L38):
добавить пункт `verificahubPath(lang)`. Якоря остаются.

Итог: **три** реальные страницы в меню — `/open-source/`, `/blog/`,
`/verificahub/`.

- Стоимость: минутная правка, риска нет.
- Потолок: три быстрые ссылки. Яндекс обычно показывает больше, и часть слотов
  он может добрать сам из популярных переходов (например, из страниц библиотек).
- Смысл есть в любом случае: держать флагманский продукт только в подвале —
  потеря.

### Вариант B. Полный — превратить якоря в страницы

Сделать `/about/`, `/experience/`, `/projects/`, `/contacts/` отдельными
маршрутами вместо секций главной. Меню тогда состоит только из настоящих URL, и
у Яндекса появляется шесть-семь честных кандидатов.

Что придётся тронуть:

- `RouteMatch` и построители путей в [src/routes.ts](../../src/routes.ts);
- `metaFor()`, `jsonLdFor()`, крошки в [src/seo.ts](../../src/seo.ts);
- `allRoutes()` → sitemap и пререндер подхватятся сами;
- `scripts/og.mjs` — своя карточка на каждый новый маршрут;
- разбор `src/pages/Home.tsx` на страницы.

Компромиссы:

- Главная худеет. Сейчас это цельная одностраничная визитка — сильная сторона
  сайта, и терять её жалко.
- Контента на `/experience/` и `/contacts/` мало; тонкие страницы Яндексу не
  нравятся.
- Работы на несколько часов, и это **необратимо дёшево только один раз**.

### Что выбрать

**Вариант A сейчас, вариант B — только если появится трафик и контент.**

Обоснование: вариант B не даёт быстрых ссылок сам по себе. Робот берёт
«наиболее посещаемые разделы», а у нового сайта их нет ни при какой структуре
меню. Разбить главную на четыре тонкие страницы ради кандидатов, которые робот
всё равно проигнорирует из-за нулевой посещаемости, — это заплатить структурой
вперёд и без гарантии.

Разумный компромисс — гибрид: вариант A + оставить якоря + вырастить `/blog/` и
`/open-source/` как разделы с реальным трафиком. Если через несколько месяцев
Вебмастер покажет, что быстрые ссылки сформировались только на два-три раздела,
тогда возвращаться к B.

## Этап 3. Название раздела Open Source (проблема 5)

`Open Source` латиницей в русском меню (`ui.nav.openSource` в
[src/i18n.ts](../../src/i18n.ts)). Как быстрая ссылка это и отобразится.

Решать **до** того, как Яндекс сформирует быстрые ссылки: переименование раздела
после — это «структура сайта изменилась», то есть удаление ссылки и
переформирование.

Варианты анкора для `ru`: `Open Source` (как есть), `Библиотеки`, `Открытый код`.
Менять URL `/open-source/` при этом не нужно и не стоит.

## Этап 4. Контент (проблема 6)

Раздел из одной статьи не наберёт переходов. Быстрая ссылка на `/blog/` появится
не раньше, чем блог станет разделом, куда действительно ходят.

Это не задача для кода, но без неё этапы 1–3 упираются в потолок.

## Чек-лист проверки

После этапа 1 — локально:

```bash
npm run build
grep -o 'href="/[a-z-]*/"' dist/index.html | sort -u   # ссылки со слешем
grep -c "<loc>" dist/sitemap.xml                       # по-прежнему 28
```

На живом сайте — ни одна внутренняя ссылка не должна отдавать 301:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -I https://ai-iskuzhin.is-a.dev/open-source/
```

В Яндекс Вебмастере — **Представление в поиске → Быстрые ссылки**. Там же видно,
сформированы ли они, и какие именно страницы робот выбрал.

Ожидание по срокам: обход робота, накопление статистики — недели, а не дни.
Быстрые ссылки могут не появиться вовсе, если сайт не наберёт посещаемость;
это соответствует правилам Яндекса, а не является дефектом.
