# YML-фиды: услуги и предложения в поиске

Конспект правил Яндекса + вывод по применимости к этому сайту. Первоисточники:
Яндекс Вебмастер → Справка → «Работа с фидом для передачи услуг и предложений»
и «Исполнители». Дата обновления страницы-первоисточника: 27.03.2026.

> **Бета.** Дополненное представление в поиске находится в режиме
> бета-тестирования. Данные из YML-файлов могут не отображаться в результатах
> поиска — это не считается ошибкой.

## Вывод для этого сайта: фид не подаём

Категория «Исполнители» предназначена для **информационных сайтов, на которых
размещаются предложения услуг от разных исполнителей** — то есть агрегаторов и
каталогов. Обогащение выдачи «предоставляется только для страниц подходящего
формата: содержащих **список объектов**».

`ai-iskuzhin.is-a.dev` — персональный сайт одного человека. Против подачи фида
работают сразу четыре требования Яндекса:

1. **Нет списка объектов.** Сет должен собирать предложения нескольких
   исполнителей, чтобы пользователь мог их сравнить. Здесь исполнитель ровно
   один, и сет из одного оффера — это не список.
2. **Обязательные поля нечем заполнить.** `price`, `param name="Рейтинг"`,
   `param name="Число отзывов"`, `param name="Конверсия"` обязательны. На сайте
   нет ни цен, ни рейтинга, ни отзывов.
3. **Данные фида обязаны совпадать с сайтом.** «Если информация в фиде и на
   сайте разная, предложения могут быть заблокированы. Если таких предложений
   большинство, может быть заблокирован весь фид.» Придуманные цены и рейтинг —
   прямой путь к блокировке.
4. **Ручная модерация.** Фид проверяется службой контроля качества и может быть
   отклонён за нарушение правил.

Подавать фид имело бы смысл, только если сайт превратится в каталог с ценами,
отзывами и несколькими исполнителями. Пока этого нет, усилия лучше направить на
[быстрые ссылки](bystrye-ssylki.md).

Остальная часть документа — справочная, на случай если такой раздел появится.

## Модель данных

Фид — это YML-файл (стандарт Яндекса на основе XML). В нём описываются
**предложения** (`offers`), объединённые в наборы — **сеты** (`sets`).

Сет отличается от **категории** (`category`): категория у предложения может быть
только одна, а сетов — несколько, потому что одно и то же предложение может
принадлежать разным сетам. Сеты перечисляются через запятую в `set-ids`.

В поисковой выдаче дополняется тот сниппет, **URL которого совпадает с URL,
заданным в сете**. Сниппет дополняется информацией из предложений, входящих в
этот сет.

Формировать файл для всего контента не обязательно: достаточно описать те сеты
(URL), которые нужно дополнить в результатах поиска.

Вся дополнительная информация о предложении задаётся элементом `param` —
универсальным элементом с текстовым контентом.

## Элементы предложения (категория «Исполнители»)

Обязательные отмечены звёздочкой.

| Элемент | Примечание |
| --- | --- |
| `name` * | Имя исполнителя, название организации или ИП |
| `url` * | URL предложения. Уникален среди всех предложений во всех фидах одного региона. Метки (UTM, Openstat, from) уникальности не создают |
| `price` * | Стоимость. Атрибут `from="true"` — задана минимальная оплата |
| `currencyId` * | Идентификатор валюты, например `RUR` |
| `categoryId` * | Идентификатор категории |
| `set-ids` * | Идентификаторы сетов через запятую: `s1,s2,s3` |
| `picture` * | Ссылка на логотип или фото исполнителя. Ссылки не должны повторяться между предложениями (одинаковое фото можно загрузить по другой ссылке) |
| `description` * | Название услуги, профессия исполнителя и пр. |
| `param name="Рейтинг"` * | Число. Для нового исполнителя или при отсутствии рейтинга — `0` |
| `param name="Число отзывов"` * | Число |
| `param name="Годы опыта"` * | Число |
| `param name="Регион"` * | Строка: страна, область, город, район города, станция метро |
| `param name="Конверсия"` * | Число, произвольное значение. Чем больше, тем лучше предложение |
| `param name="Ссылка на телефон"` | Строка |
| `param name="Ссылка на чат"` | Строка |
| `param name="Ссылка на создание заказа"` | Строка, если не совпадает с `url` предложения |
| `param name="Ссылка на профиль исполнителя"` | Строка |
| `sales_notes` | Заметки: «Цена договорная», «Цена за метр» |
| `expiry` | Срок гарантии |
| `param name="Исполнитель проверен"` | `true` / `false` (по умолчанию `false`) |
| `param name="Организация"` | `true` / `false` |
| `param name="Выполняется удаленно"` | `true` / `false` |
| `param name="Выполняется по адресу исполнителя"` | `true` / `false` |
| `param name="Выполняется по адресу заказчика"` | `true` / `false` |
| `param name="Бригада"` | `true` / `false` |
| `param name="Об исполнителе"` | Строка |
| `param name="Отзыв на исполнителя - X"` | Строка. `X` — номер отзыва (1–5). Атрибут `unit` задаёт оценку: `unit="4.9"` |
| `param name="Другая услуга исполнителя - X"` | Строка. `X` — номер услуги (1–5) |

Можно создавать собственные необязательные `param`. Часть информации из них
может не отображаться в текущих форматах обогащения выдачи, но будет учитываться
при ранжировании предложений внутри сета и может появиться в новых форматах.

### Особенности

**Имена исполнителей в одном сете не должны повторяться** (значение `name`).

## Категории бизнеса (какие фиды бывают)

- **Недвижимость** — продажа или аренда квартир, офисов, домов, других построек
- **Вакансии** — предложения работы
- **Транспортные средства** — продажа автомобилей, мотоциклов и др.
- **Образовательные онлайн-курсы и уроки** — например, курсы программирования
- **Исполнители** — бытовые и другие услуги, например перевозка мебели
- **Врачи** — услуги врачей, например приём педиатра
- **Рекомендации событий** (β) — продажа билетов на развлекательные события
- **Банковские услуги** — вклады, займы, ипотека

О передаче данных о **товарах** — в справке Яндекс Товаров, не здесь.

## Шаг 1. Подготовка данных

1. Сформировать YML-файл по требованиям своей категории бизнеса.
   Поддерживается расширение `.xml`, `.yml` или архив gzip.
2. Если у сайта есть поддомены (`spb.example.com`), предложения для них
   размещаются **в фидах основного домена** (`example.com`).
3. Разместить YML-файл на сайте — в корневом или другом каталоге. Файлы не
   попадают в результаты поиска, но индексируются роботом, поэтому каталог не
   должен быть закрыт от роботов Яндекса.
4. Настроить **автообновление** фида, чтобы данные не расходились с сайтом.
5. Убедиться, что HTTP-заголовок `Content-Type` от сервера содержит один из
   типов: `application/xml`, `application/octet-stream`, `text/xml`,
   `application/gzip`, `application/x-gzip`.

## Шаг 2. Загрузка фида

> Не загружайте один и тот же фид или фид с идентичным содержимым для нескольких
> категорий и поддоменов.

1. Авторизоваться на Яндексе, добавить сайт в Вебмастер и подтвердить права
   (или получить доступ у пользователя с ролью «Владелец»).
2. Перейти на страницу **Услуги и предложения в поиске → Фиды и ошибки**.
3. Нажать **Загрузить фид**.
4. Выбрать категорию бизнеса.
5. Указать регион. Если предложения доступны на одинаковых условиях везде —
   выбрать «Россия». Можно выбрать несколько значений.
6. В поле **Ссылка на файл с предложениями** указать URL вида
   `https://example.com/feed.yml`.
   При настроенной авторизации логин и пароль передаются вместе с URL:
   `https://yandex:WE9h4FfBml@example.com/feed.yml`.
7. Нажать **Готово**.

Вебмастер проверит фид. Ошибки появятся на странице **Услуги и предложения в
поиске → Фиды и ошибки** — кнопка **Ошибки** напротив фида. После исправления
Вебмастер перепроверит фид сам либо по кнопке **Перепроверить**.

Дополнительно фид несколько дней проверяет служба контроля качества. Можно
настроить уведомления о результатах проверок.

## Удаление фида

**Способ 1 — удалить в Вебмастере.** Услуги и предложения в поиске → Фиды и
ошибки → напротив фида → **Удалить фид**.

**Способ 2 — очистить фид от предложений:**

```xml
<?xml version="1.0" encoding="utf-8" standalone="yes"?>
<yml_catalog date="2018-07-17 12:10">
  <shop>
    <name>ТестУдаления.Услуги</name>
    <company>ООО ТестУдаления.Услуги</company>
    <url>uslugi.remove_test.s3.yandex.net</url>
    <email>uslugi@yandex.ru</email>
    <currencies>
    </currencies>
    <categories>
    </categories>
    <sets>
    </sets>
    <offers>
    </offers>
  </shop>
</yml_catalog>
```

## Условия использования

Сайт несёт ответственность за корректность данных, соответствие предложений
тематике и за распространение незаконной информации. При нарушении условий
Яндекс вправе не использовать данные сайта для изменения представления в выдаче.

Данные из фида могут обогащать органический результат, **когда это увеличивает
профицит** (метрику полезности для пользователя) поисковой выдачи.

Положение ответа в выдаче определяется общими принципами ранжирования: более
высокие позиции получают страницы, наиболее релевантные запросу. Порядок
карточек внутри ответа определяется данными о взаимодействии пользователей с
карточками — для максимизации конверсии и профицита.

Чтобы при ранжировании предложений учитывались данные о конверсиях, Яндекс
рекомендует установить **Яндекс Метрику**. На этом сайте Метрики сейчас нет.
